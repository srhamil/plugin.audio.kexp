================================================================================
1. WHAT THIS IS
================================================================================
Kodi audio add-on (plugin.audio.kexp, v0.0.2 PROTOTYPE, provider
srhamil, GPL-3.0-or-later): KEXP 90.3 Seattle live stream + the
station's public TWO-WEEK ARCHIVE, browsable by day / program / host,
with now-playing metadata REPLAYED IN SYNC during archive playback.
Companion reference: kexp-archive-api.md (the reverse-engineered API
map, curl-verified 2026-07-19/20) -- read it alongside this.

Origin: spun out of plugin.audio.internetradio (which keeps its own
live-KEXP station). Built by porting that add-on's validated
architecture; it is the parent design. Same target environment as all
of Simon's audio add-ons: RPi4 + DAC appliance, Kodi 21 Omega on
LibreELEC, Aeon Nox SiLVO, Bravia/CEC, stdlib only. Same owner
workflow rules: design discussion before code, complete
compile-checked file deliverables, type hints, new-format settings.xml
+ strings.po, log prefixes [plugin.audio.kexp/plugin|/service|/data],
verbose INFO during shakedown then LOGDEBUG.

STATUS: v0.0.1 generated 2026-07-20 as a no-further-input prototype at

2. ARCHITECTURE
================================================================================
* default.py -- plugin/router. Root: "Listen live" (stream URL as item
  path, property kexp_mode=live -- the internetradio pattern
  unchanged) + folders Shows by day / Programs / DJs (user-facing
  "DJs"; code/API/action strings stay "host*" to match KEXP's own
  vocabulary). ALL folder listings use setContent("albums") (view-mode
  lesson from internetradio) so SiLVO offers wall/grid views. Shows-by-
  day cells carry a generated SVG date-card thumb (kexpdata.date_tile:
  orange KEXP header, big day numeral, weekday; cached per date in
  profile/date_tiles/; Kodi renders SVG art natively, no image lib on
  device) so the wall reads as a date grid like the web page. DJ cells
  use the DJ's photo (image_uri) as thumb + their most-frequent program
  as label2 (via setAlbum/setArtist). Show-row labels are context-
  trimmed: day folder = "HH:MM Program with DJ"; program folder =
  "Wkd Mon DD  HH:MM  with DJ"; DJ folder = "Wkd Mon DD  HH:MM
  Program". The player info-tag title always keeps the full show name.
  ARCHIVE PLAYBACK RESOLVES AT PLAY TIME via setResolvedUrl -- the
  family's first deliberate departure from the no-resolve-handler
  rule, for API frugality (each URL costs a get_streaming_url call;
  resolving at listing time would burn 6-8 per folder). The resolved
  item gets kexp_mode=archive, setMimeType("audio/mpeg") +
  setContentLookup(False) (skip Kodi's probe = no wasted AIS session).
* resources/lib/kexpdata.py -- data layer: get_json (GET only; the
  API 405s HEAD), fetch_shows() (paginates /v2/shows/?ordering=
  -start_time&limit=100 until results age past 14 days, max 12 pages,
  15-min disk cache in profile/shows_cache.json), group_by_day /
  unique_programs / unique_hosts (client-side slicing of the one
  cached list -- avoids unverified server filter params entirely),
  resolve_stream() (get_streaming_url wrapper), write_session/
  read_session (profile/archive_session.json plugin->service handoff),
  date_tile() (cached SVG date cards). NOTE: default.py parses its own
  YYYY-MM-DD day keys via a manual int-split, NOT datetime.strptime --
  strptime lazily imports _strptime and Kodi's per-invocation
  interpreter can leave that reference dead (datetime.strptime -> None),
  which crashed v0.0.1 browse (finding #1). Never use strptime in Kodi.
* service.py -- background service, 2s tick. BaseHandler carries TAG
  DEFENSE (internetradio's hard-won lesson: Kodi's ICY handling stomps
  updateInfoTag pushes; compare MusicPlayer.Title/Album InfoLabels vs
  last-pushed each tick, re-push on drift; push_tag builds on
  getPlayingItem() and sets album unconditionally so empty clears).
  - LiveHandler: port of internetradio's field-validated KexpHandler
    (plays/?limit=1, show-label cache, airbreak handling), minus
    history.
  - ArchiveHandler: the new trick. Session handoff gives sg_url,
    offset (sg-offset), file_start_epoch (= requested start - offset),
    show_label, art. One-shot seekTime(offset) executed from the
    service tick once getTotalTime()>0 (seeking inside onAVStarted is
    flaky; gives up to 0:00 after ~40s with a warning). Then every
    archive_poll seconds: broadcast moment = file_start_epoch +
    player.getTime(); query /v2/plays/?limit=1&ordering=-airdate&
    airdate_before=<moment UTC Z>; SANITY CHECK the returned airdate
    (must be <= moment and within 3h) -- if it fails, the filter is
    unsupported and we fall back to show-identity display with a loud
    log line instead of showing live metadata as archive metadata.
  - RadioPlayer._identify(): kexp_mode item property first; fallback
    matches getPlayingFile() against LIVE_STREAM_URL or the session
    file's sg_url (compared session-less, pre-'?', because the AIS
    redirect appends listeningSessionID). Log records which path won
    -- this answers the does-setResolvedUrl-preserve-properties
    question on first device run.
* Settings: live_poll (5-120s, def 20), archive_poll (5-60s, def 10),
  bitrate (64/128/256, def 128; label says effect unverified).
* Icon: generated placeholder (deliberately not the KEXP logo).

3. KEY API FACTS (full detail in kexp-archive-api.md)
================================================================================
get_streaming_url/?bitrate=N&timestamp=ISO -> {sg-url, sg-url-next,
sg-offset}. One MP3 file per show; files start ~10 min before the
nominal hour -- NEVER schedule math, always sg-offset. URLs stable/
deterministic/unsigned. StreamGuys host = AIS server, 302-wraps a
listeningSessionID (Kodi follows natively; never cache session URLs).
Files: audio/mpeg, Accept-Ranges bytes (native seeking), ~135 kbps for
bitrate=128. v2 shows carry start_time + program/host names + artwork;
no end_time (show N ends at show N+1's start). Plays are published
first, annotated later (comment arrives late -- internetradio lesson).

FINDINGS FIXED in v0.0.2 (first device test -> one patch pass):
  #1 datetime.strptime is None in Kodi (lazy _strptime import dies with
     the interpreter) -> crashed all day browsing. Fixed: manual
     int-split parse. VERIFIED from the log that ordering=-start_time IS
     honored (3 pages, 120 shows, clean window stop) -- watch item #5
     below now CONFIRMED.
  #2 sliced listings showed weekday+time only (ambiguous over 14 days)
     -> full "Wkd Mon DD  HH:MM" in program/DJ folders, context-trimmed
     (drop the folder's own dimension: program name in DJ folders, DJ
     in program folders).
  #3 "Hosts" reads as servers to a sysadmin -> user-facing "DJs".
  #4 Shows-by-day now a date-tile grid (generated SVG cards + albums
     content). Web page has NO week structure (just flows cells), so we
     match that -- no weekday-column alignment needed.
  #5 DJs now a photo-tile grid (DJ photo + most-frequent program text).
